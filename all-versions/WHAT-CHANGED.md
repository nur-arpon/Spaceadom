# Spaceadom — what changed in each version

Every installer ever built lives in this folder.

**Use the `setup.exe`.** It installs into your own user folder and never asks
for an admin password.

The `.msi` was dropped at 1.0.41 (see that row) and **came back at 1.0.54** for
anyone whose workplace requires that format — it installs for the whole PC and
asks for admin once. So 1.0.41–1.0.53 have only a `setup.exe`; everything
before and after has both. Install ONE, never both.

**To go back to any version:** run its `setup.exe`. It installs into your own
user folder, needs no admin password, and replaces whatever is there — you do
not need to uninstall first.

**One warning about the old `.msi` files, if you ever run one:** an `.msi`
installs to `C:\Program Files` instead, which is a SEPARATE copy. Windows then
has two Spaceadoms that cannot see each other, and both try to start when you
log in — two programs fighting over your spacebar. If you ever do it by
accident, uninstall "Spaceadom" from Add/Remove Programs and reinstall from a
`setup.exe`.

**Your settings are not touched** by switching versions — profiles and bindings
live in `%APPDATA%\Spaceadom\config.json`, separate from the app. Rolling back
is safe.

**Missing: 1.0.28.** Deleted at your request on 2026-08-14 — it was the first
attempt at the toast/HUD transition and it made the HUD feel delayed. Every
other version is here, 1.0.0 through 1.0.74, including the few that were
superseded within minutes on 2026-08-20 (1.0.64, 1.0.66, 1.0.67, 1.0.68) —
those are wrong turns, and they are kept so the record is honest rather than
tidy. Their rows say what each one got wrong.

## 2026-08-29 — apps stop relaunching instead of minimising, and the guide stops outliving your hold

| Version | What changed |
| --- | --- |
| **1.0.91** | **Three fixes, no new shortcuts.** (1) **Apps like WhatsApp relaunched on every press instead of minimising.** The fault was in how the app was bound, not which app it was: a key stored as a link (`whatsapp://`) rather than as a program on disk could be STARTED but never FOUND again, so the launch/focus/minimise cycle had nothing to cycle. (3) **Crash reports can now see the parts that were invisible.** Anything going wrong in the app's own screens, and the "still running but quietly broken" states — a deaf hook, a guide that stopped drawing — are now reported instead of being filed below the reporting threshold. The "Don't send logs" switch in Settings still stops all of it. |

## 2026-08-28 — the shortcut guide stops switching itself off, and startup gets out of your way

| Version | What changed |
| --- | --- |
| **1.0.90** | **Two fixes, both about the app getting out of its own way. (1) The Space-hold guide no longer switches itself off.** Plugging a monitor in or out — or unplugging one, or waking the laptop on a dock — could leave the guide, and the sounds with it, dead until you quit Spaceadom and started it again. What was happening: the app rebuilds the guide window whenever your displays change, and a single plug-in can report itself as three or four separate changes in a couple of seconds, so several rebuilds ran on top of each other. One of them would find the window another had just made, decide the rebuild had failed, and switch the guide off — permanently, because nothing ever tried again. Four things changed. Rebuilds now run strictly one at a time and actually wait for each other. A display change has to hold still for six seconds before anything is rebuilt, so one plug-in produces exactly one rebuild instead of four. If a rebuild finds the window already there, it now adopts it and reconfigures it instead of calling that a failure. And in the one case where the window really is gone, the app keeps quietly retrying on its own until it comes back. **You should never have to restart it to get the guide back again.** **(2) Shortcuts work the instant you log in.** Spaceadom waits ten seconds at login before drawing anything, so it doesn't fight Windows for the disk while your desktop is still assembling. That wait used to hold up everything, including the spacebar itself. Now only the drawing waits: the moment you are logged in, holding Space and tapping a key launches, focuses and minimises exactly as it should — the guide simply doesn't draw for the first few seconds. Startup also got faster: 1.47 seconds down to 0.89. |
